# Wildfire — แดชบอร์ดเจ้าหน้าที่ + หลักการและเวลาตรวจพบ

**แอปสองส่วน:** https://saratchai1.github.io/wildfire/

1. **แดชบอร์ดเจ้าหน้าที่** — `#dashboard` เปิดเป็นค่าเริ่มต้น: ภาพรวมเหตุจำลอง, แผนที่ถนนและสถานี 9 จุด, สถานะเชื่อมต่อ, PM2.5/CO, อุณหภูมิ/ความชื้น/ลมจำลอง, กราฟย้อนหลัง, ลำดับเหตุการณ์, เล่น/พัก/เลื่อนเวลา และรับทราบเฉพาะฉาก
2. **หลักการและเวลาตรวจพบ** — `#principles`: เลือกจุดเริ่มไฟและลมพัดไป 8 ทิศ ปรับความเร็ว/เวลาจนเริ่มมีควัน แยกเวลาควันเดินทางถึงจากเวลาเข้าเกณฑ์ PM+CO แสดงตารางเปรียบเทียบ 8 ทิศและเปิดฉากเดียวกันในแดชบอร์ดได้

**โมเดลเดียวกันทั้งสองส่วน:** เวลาแจ้งในตารางตรงกับเหตุการณ์/สถานะในแดชบอร์ด ไม่ใช่ตัวเลขสมมติคนละชุด ไม่มี backend, sensor feed, การส่งแจ้งเตือนจริง หรือการเก็บรับทราบในระบบกลาง

## ของเดิมยังอยู่

- แผนติดตั้ง 9 จุด ตัวคำนวณพลังงาน และการคัดกรอง 197 จุด × 16 ทิศ: [planning.html](planning.html)
- รุ่นแปดจุด: [v1.html](v1.html)
- แหล่งไอเดียเดิม `bdteamditto/fire` ไม่ได้ถูกแก้
- คงพิกัด `data/plan.js` เดิมทั้ง 9 จุด E1–E5 / W1–W4 รอบ 18.813555556, 98.862250000; Solar + Battery ทุกจุด พื้นที่ศึกษารัศมี 2 กม. = 12.57 ตร.กม. **ไม่ใช่รัศมีรับประกันตรวจไฟ**

## หลักการเวลา

T+0 = ไฟเริ่มในฉากสมมติ ตั้งค่าเริ่มมีควันทันที (0 นาที) หรือหน่วงได้ การคำนวณแจ้งใช้สูตรความเข้มข้น PM/CO สังเคราะห์เดิมผ่าน `siting.js` แล้วเผื่อเวลาอุปกรณ์รวม 2 นาที (อ่าน 30 วินาที + ประเมินต่อเนื่อง 60 วินาที + ส่ง 30 วินาที) สูตรประเมิน threshold ทุก 0.5 นาที เป็นสมมติฐานแบบสาธิต ไม่ใช่ SLA หรือค่าที่วัดจริง

**เวลาแจ้ง = ก่อนมีควัน + เวลาจนความเข้มข้นผ่านเกณฑ์ + เวลาอุปกรณ์** เวลาเดินทางรวมอยู่ในขั้นถึงเกณฑ์แล้ว ไม่บวกซ้ำ เวลาควันถึงในกรอบเรขาคณิตจะแสดงแยกต่างหากและอาจเป็นคนละสถานีกับจุดเข้าเกณฑ์ก่อน ควันถึงไม่ได้แปลว่าความเข้มข้นพอ

ลมสงบ ไม่มีสถานีพร้อม ไม่เข้าแนวควัน และไม่ถึงเกณฑ์ใน 60 นาที ไม่แสดงเป็นศูนย์หรือพื้นที่ปลอดภัย ไม่มีการยืนยันไฟอัตโนมัติ การเปลี่ยนเงื่อนไขเริ่มฉากใหม่และล้างการรับทราบ แต่สลับสองส่วนจะใช้เงื่อนไขเดิมและพักการเล่น

ยังไม่จำลองควันยกตัว เรือนยอด ลมแปรปรวน หรือข้อมูลเชื้อเพลิงจริง ไม่รวมเวลาตรวจยืนยันของเจ้าหน้าที่ พิกัดยังต้องสำรวจสิทธิ์เข้าถึง แดด ไหล่ทาง และ RF; แท็กทางดิน/การเข้าถึงใน OSM ยังเก็บไว้ตามต้นทาง

## ทดสอบและเปิดใช้งาน

แอปไม่มี dependency ภายนอกที่จำเป็นต่อถนน/ภูมิประเทศ/การจำลอง สามารถเปิดโฟลเดอร์ครบผ่าน `index.html` หรือ HTTP server ภาพดาวเทียมออนไลน์เป็นตัวเลือกและมี fallback

```sh
node --test tests/*.test.cjs
node scripts/build.cjs
python -m http.server 4173 --directory site
```

Browser proof: `pip install playwright==1.55.0` แล้ว `python -m playwright install chromium`; รัน `python tests/browser.py`, `python tests/history_browser.py`, `python tests/siting_browser.py`, `python tests/console_browser.py` ขณะ server ทำงาน

Workflow validate-deploy ตรวจ regression ของเก่าและสองส่วนใหม่ก่อน deploy แล้วตรวจ HTTP และ exact commit/appVersion ใน `version.json` ผล QA และภาพ desktop/mobile อยู่ใน Actions artifact `wildfire-qa-and-portable-app` ผล browser PASS ไม่ใช่ผล commissioning ภาคสนาม
